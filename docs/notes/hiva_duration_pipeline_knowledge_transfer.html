Training Action Semantics

The LIBERO LeRobot dataset stores each action target as a 7-D float32 vector. The dataset metadata names this feature generically as actions with shape [7], and the local LIBERO wrapper exposes a 7-D action space bounded by [-1, 1]. In our finetuning, replay, and evaluation scripts we run LIBERO with --env.control_mode=relative, so the simulator controller interprets the pose part of the action as relative commands rather than absolute end-effector targets.

Action Slice Meaning Important Caveat
action[0:3] Relative Cartesian translation command, commonly read as dx, dy, dz. This is a delta command to the controller, not an absolute world position.
action[3:6] Relative 3-D orientation command. It is safe to describe this as a relative rotation delta. Be careful calling it literal pitch/yaw/roll unless the lower-level robosuite controller convention is being discussed explicitly; for this pipeline, the important fact is that it is not an absolute orientation target.
action[6] Continuous gripper command in [-1, 1]. This is treated as an absolute command signal, not a delta. In the sidecar logic, positive values above threshold mean close, negative values below threshold mean open, and near-zero values hold the previous command-side gripper state.

So the short answer is: yes, the training action is relative translation, relative rotation, and an absolute continuous gripper command. The one wording correction is that the rotation should be documented as a relative 3-D orientation delta, not necessarily as literal Euler pitch/yaw/roll. During model training the action tensor may be normalized by LeRobot preprocessing/statistics, but semantically the target remains this same 7-D LIBERO controller command. SmolVLA predicts future chunks of these commands, for example 50 future actions when chunk_size=50.

This distinction matters for duration labels: gripper switch labels are derived from the final action dimension together with observed gripper qpos, while the translation and rotation dimensions are not used directly to define the gripper-switch duration target.

HP HiVA: Canonical Hold-Pad Coefficients

Motivation

HP HiVA is the current coefficient-model direction. The earlier coefficient sidecars fit coefficients in a duration-specific coordinate system: a window with duration 6 was fit on a shorter effective basis than a window with duration 15. That is convenient for offline reconstruction, but awkward for a single model head because the meaning of coefficient index k changes with the duration. HP HiVA fixes this by using one canonical Dmax=15 time axis and one shared cubic B-spline basis for every training sample.

The duration token now decides how many decoded micro-actions to execute, while the coefficient tokens always describe a canonical hold-padded macro target. This keeps the coefficient regression space fixed, makes coefficient normalization well-defined, and lets the model learn one suffix shape independent of the selected duration.

Current HP Sidecar Setting

The current HP dataset-preparation setting uses recomputed duration set {6, 10, 15}, canonical hold-padding, fixed cubic B-splines with K=10 control coefficients, degree p=3, and Dmax=15. The fixed-shape coefficient fields are:

Field Shape / Meaning
hiva_theta_tr_raw [10,3] raw translation B-spline coefficients
hiva_theta_rot_raw [10,3] raw command-space cumulative rotation B-spline coefficients
hiva_theta_grip_raw [10,1] raw absolute gripper B-spline coefficients
hiva_P_tr_hold_raw [15,3] hold-padded cumulative translation target
hiva_rho_rot_hold_raw [15,3] hold-padded cumulative command-space rotation vector target
hiva_G_grip_hold_raw [15,1] hold-padded absolute gripper command target

For each sample, the final duration is still D = min(Ds, Dp), where Ds comes from gripper switch/qpos safety and Dp comes from pure-contact-frame safety. Duration labels are recomputed for the candidate set {6,10,15}; they are not remapped from older {1,3,8} or {4,8,12} labels.

The hold-padded target over 15 micro-steps is:

  • Translation: use real relative translation actions until D, then set translation deltas to zero so the cumulative position holds.
  • Rotation: compose real command-space SO(3) deltas until D, then set rotation deltas to zero so the cumulative rotation holds.
  • Gripper: use real absolute gripper commands until D, then repeat the last command.

This is why the sidecar stores both coefficient labels and raw hold-padded targets: hiva_P_tr_hold_raw, hiva_rho_rot_hold_raw, and hiva_G_grip_hold_raw. A direct verification on rows with d=6, d=10, and d=15 showed zero difference between the stored sidecar targets and targets recomputed from the raw dataset actions.

HP Model Suffix

With K=10, the HiVA coefficient action-expert suffix has: 

1 duration token
+ 10 translation coefficient tokens
+ 10 rotation coefficient tokens
+ 10 gripper coefficient tokens
= 31 suffix tokens

The suffix order is [duration][translation coeffs][rotation coeffs][gripper coeffs]. In code, hiva_suffix_len = 1 + 3 * hiva_k, so hiva_k=10 gives 31. The running HP finetuning log also prints HIVA_K=10 and HIVA_SUFFIX_LEN=31.

Two suffix-attention modes are currently important:

  • full: duration and all coefficient tokens are one bidirectional suffix block.
  • duration_prefix: duration does not attend coefficient suffix tokens, while coefficients attend duration and each other.

HP Training Objective

HP HiVA trains the coefficient suffix with flow-matching losses for translation, rotation, and gripper coefficients, plus a discrete duration cross-entropy loss over classes {6,10,15}. Current sweeps compare duration-loss reductions such as duration_noisy_weights and ce_mean, with hiva_duration_noisy_loss_weight=1.0 and hiva_duration_noisy_sigma=0.25.

During inference or GT-coefficient replay, predicted or saved coefficients are decoded into 15 candidate micro-actions, and only the first predicted duration actions are executed before the next observation.

Rotation Coefficient Labels

Chosen Method: Command-Space Cumulative Rotation

For a HiVA rotation coefficient head that must decode back into executable LIBERO actions, use command-space cumulative rotation targets. The raw LIBERO rotation command is action[3:6]. In the OSC_POSE controller configuration, raw values in [-1, 1] are scaled to axis-angle radians by delta_rotvec = 0.5 * action[3:6].

For a segment starting at frame s with duration d, define: 

DeltaR_{s+tau-1} = Exp(0.5 * action_{s+tau-1}[3:6])
C(0) = I
C(tau) = C(tau-1) @ DeltaR_{s+tau-1}
y_rot(tau) = Log(C(tau))

Fit cubic B-spline coefficients to the cumulative command-space rotation vectors: 

coef, *_ = np.linalg.lstsq(Phi, y_rot, rcond=None)

At inference, predicted coefficients are decoded into cumulative rotations and then converted back to per-step raw LIBERO rotation actions by SO(3) differencing: 

y_hat = Phi @ coef_pred
C_hat[tau] = Exp(y_hat[tau])
DeltaR_hat[tau] = inv(C_hat[tau-1]) @ C_hat[tau]
delta_rotvec[tau] = Log(DeltaR_hat[tau])
raw_action_rot[tau] = delta_rotvec[tau] / 0.5

Do not recover rotation deltas by simple subtraction of adjacent rotation vectors. Rotations compose on SO(3), so the per-step command must come from inv(C_hat[tau-1]) @ C_hat[tau]. 

from scipy.spatial.transform import Rotation as R
import numpy as np

OSC_ROT_SCALE = 0.5

def command_space_cumulative_rotvec(action_chunk):
    C = R.identity()
    y = []
    for raw in action_chunk[:, 3:6]:
        dR = R.from_rotvec(OSC_ROT_SCALE * np.clip(raw, -1.0, 1.0))
        C = C * dR
        y.append(C.as_rotvec())
    return np.asarray(y)

def fit_rotation_coeff(action_chunk, Phi):
    y = command_space_cumulative_rotvec(action_chunk)
    coef, *_ = np.linalg.lstsq(Phi, y, rcond=None)
    return coef

def decode_rotation_coeff(coef, Phi):
    y_hat = Phi @ coef
    raw = []
    prev = R.identity()
    for cur in R.from_rotvec(y_hat):
        dR = prev.inv() * cur
        raw.append(dR.as_rotvec() / OSC_ROT_SCALE)
        prev = cur
    return np.asarray(raw)

Alternative: Chunk-Start Quaternion / Observed EEF Rotation

The observed EEF method uses the realized end-effector orientation instead of the raw controller command. With observed quaternions, the label is: 

q_rel(tau) = quat_distance(q_{s+tau-1}, q_{s-1})
y_obs(tau) = quat2axisangle(q_rel(tau))

In the current LeRobot LIBERO dataset, this can be implemented from observation.state, whose layout is eef_pos(3) + eef_axisangle(3) + gripper_qpos(2): 

abs_rotvec = states[:, 3:6]      # frames s-1, s, ..., s+d-1
R_start = R.from_rotvec(abs_rotvec[0])
R_abs = R.from_rotvec(abs_rotvec[1:])
y_obs = (R_abs * R_start.inv()).as_rotvec()

This is geometrically accurate for the motion that actually happened, including controller tracking, interpolation, dynamics, contact, and simulator response. It is not a good target if the coefficient head must decode directly to raw LIBERO action[3:6]. On the nonzero sample episode=34, start_frame=352, duration=8, task=2, the observed-EEF B-spline fit had excellent cumulative state reconstruction error, 1.37e-4 radians per component, but decoding it back to raw LIBERO rotation actions gave RMSE = 0.1630 and max_abs_diff = 0.2930 versus the original action[3:6].

Therefore, the current recommendation is: use command-space cumulative rotation for the executable HiVA rotation coefficient head; keep the chunk-start quaternion / observed EEF method for diagnostics or for a separate state-trajectory prediction target.

Duration Label Semantics

Classes

  • duration_label=6: shortest always-valid fallback horizon.
  • duration_label=10: medium horizon, valid in approach-safe regions.
  • duration_label=15: longest horizon, used when the model is safely away from switch/contact regions.
  • duration_class: class index mapping 6 -> 0, 10 -> 1, 15 -> 2.

When the duration set changes, the horizon-safe dense labels must be recomputed with the new set. Do not remap older {1,3,8} or pilot {4,8,12} labels into {6,10,15}; the valid-duration regions depend directly on the candidate durations.

Final Label Formula

For each frame, the sidecar stores three related duration labels:

  • duration_label_s: switch/qpos-derived horizon-safe duration label.
  • duration_label_p: pure-contact-derived horizon-safe duration label.
  • duration_label: final training label, computed as min(duration_label_s, duration_label_p).

This makes PCF annotations a conservative override: if pure-contact metadata says a frame is near a contact event, it can shorten the horizon even when the gripper-switch label alone would allow a longer duration.

How Gripper Switch Labels Are Created

The gripper-switch side of the labeler is implemented in /home/jongwoopark/lerobot/src/lerobot/scripts/build_hiva_duration_sidecar.py.

  1. Read each episode from the LeRobot parquet dataset with columns such as index, episode_index, frame_index, task_index, action, observation.state, and timestamp.
  2. Convert the final action dimension into a command-side close/open state: positive values above a small threshold mean close, negative values mean open, and near-zero values hold the previous state.
  3. Convert the final two state dimensions into measured gripper width; estimate an observed qpos open/closed state using percentile-based hysteresis thresholds plus fixed LIBERO-friendly clamps.
  4. Detect command switches and qpos switches as state changes. Same-type switches are merged within merge_window=3 frames.
  5. Pair command and qpos switches monotonically within match_window=20 frames. The dynamic-programming pairing maximizes the number of valid pairs and then minimizes total frame distance.
  6. Recover one-sided detections into valid switch zones when possible. For unmatched command switches, the qpos endpoint is estimated by the later frame closest to the relevant qpos threshold. For unmatched qpos switches, a command frame is synthesized three frames earlier.
  7. For each frame, compute a frame context relative to valid switch zones and assign a horizon-safe label from the requested duration set. For the current HP HiVA sidecar this set is {6, 10, 15}, where 6 is the always-valid fallback, 10 is used in approach-safe regions, and 15 is used in center/free regions.

dist_to_switch is zero inside a valid switch zone. Otherwise, it is the minimum frame distance to a valid command or qpos switch endpoint. It is independent of PCF distance.

How Pure-Contact Metadata Is Created

Pure-contact frame detection is implemented by /home/jongwoopark/lerobot/src/lerobot/scripts/detect_pure_contact_pcf_replays.py. The refresh wrapper is /home/jongwoopark/lerobot/src/lerobot/scripts/update_purecontact_pcf_metadata.sh.

The detector uses language/task filtering to identify candidate pure-contact tasks, replays expert actions in LIBERO/MuJoCo, checks gripper-object contacts, and verifies the contact using target joint/object movement gates. The PCF is the contact onset frame that passes these checks.

  • pcf: detected pure-contact frame.
  • contact_interval: contiguous contact interval beginning at the PCF.
  • case_category: pure-contact case grouping.
  • purecontact_keyword and purecontact_verb: target object and manipulation verb.
  • reset_mode and seed: replay initialization metadata needed to reproduce the detection.
  • movement_window, movement_threshold, same_sign_k: verification parameters.

Finetuning Notes

  • Offline finetuning does not need LIBERO/MuJoCo simulation construction when EVAL_FREQ=0.
  • The duration sidecar does not create extra training samples. It adds labels to the existing frame-indexed LeRobot samples.
  • SmolVLA uses chunk_size=50; each frame sample contains current observation/state/text and a future action chunk. A 100-frame episode contributes about 100 samples, with future actions padded/clamped near the episode end.
  • HP HiVA uses chunk_size=15 and n_action_steps=15 because the coefficient suffix decodes a canonical 15-step macro, then executes only the predicted duration in {6,10,15}.
  • The HP coefficient model initializes compatible base SmolVLA weights from /home/jongwoopark/lerobot/smolvla_libero with load_vlm_weights=false, because the checkpoint already contains the LIBERO-finetuned VLM/action-expert weights.
  • The recent memory optimization uses one VLM prefix forward and two action-expert suffix forwards for duration training when prefix-cache reuse is enabled.
  • For the clean-plus-noisy ablation, the clean duration loss uses duration_loss_weight; the noisy duration loss uses duration_noisy_loss_weight.

Evaluation Notes

  • The overlay is implemented inside src/lerobot/scripts/lerobot_eval.py.
  • When policy.config.use_duration_head is true, each rendered frame is annotated with D=<last execution horizon> INF=<duration inference count>.
  • For bigtoken, the overlay script overrides --policy.duration_sidecar_path to the bigcornea NFS sidecar path, because checkpoints may remember the original training server path in their config.

Decoded Coefficient Replay Notes

Raw-action replay executes the saved dataset action at every environment step. Decoded HiVA replay also steps the environment once per frame, but the action stream is built by greedy macro segments. At segment start frame t, the script reads duration_label=d, decodes exactly d actions from the coefficient row at frame t, fills episode_actions[t:t+d], and jumps to t+d. It does not decode every dense frame window and execute all overlapping windows.

This explains episode 539: a dense diagnostic at frame 23 showed a large overlapping-window rotation max action diff of about 3.281, but greedy replay did not use frame 23 as a segment start. The frame lies inside the segment that started at frame 15. The generated decoded replay used 22 segments, had mean_segment_rmse_vs_dataset=0.00203, max_segment_abs_diff_vs_dataset=0.07743, and succeeded with SC.
